# Rosebud Probe

同じAndroid端末上のChrome／Braveの**内部音声を取得できるか調べる小さなアプリ**です。バージョン **0.2.0／versionCode 2**、アプリID `jp.hyoutan.rosebud`。起動確認版0.1.0と同じID・このMacのデバッグ署名で上書きできます。

開始・停止、RMS／ピークのメーター、通知からの停止、時刻付き診断ログと共有を備えます。入力はAudioPlaybackCaptureのみ。録音権限は内部音声にも必要ですが、マイクへ切り替える処理はありません。生音声・映像の保存、アプリ自身による外部送信、PC通信、Bluetooth制御は行いません。

2026-10-19、CPH2199で **Brave＋有線の取得・再生／停止への追従と、Wake Lockなしの画面オフ約8分20秒**を確認しました（USB充電中）。ビルド・Lint・単体テスト6件も成功。Chrome、10分以上、非充電条件、共有先での読み取り、許可拒否・取り消しは未検証です。

対象は **CPH2199／Android 12／ColorOS V12**。ビルド成功と取得成功は分けて扱います。次の担当者は [引き継ぎ資料](docs/handoff.md) から読めます。最新の実機結果は [docs/verification.md](docs/verification.md)、実装・公式仕様の根拠は [docs/audio-probe.md](docs/audio-probe.md)、構築済みの環境は [docs/environment.md](docs/environment.md) を参照してください。

## まずスマホで使う

APKを導入済みなら、スマホのロックを解除し、ホーム画面またはアプリ一覧から **Rosebud Probe** を開きます。許可画面はインストール時には出ません。アプリ内の **「取得を開始」** を押すと表示されます。

1. 有線イヤホンを接続します。比較するブラウザをBrave／Chromeから選び、メモに再生元・有線・試験条件を記入します。この選択は記録用で、他アプリの取得対象を制限するものではありません。他の音声アプリは止めてください。
2. 初回は **Wake Lockのチェックを外したまま**、端末の電池設定も変えずに試します。スマホの省電力モードや充電状態もログへ記録されます。
3. **「取得を開始」** を押します。
4. 録音の確認が出たら「アプリの使用時のみ」などの許可を選びます。内部音声の取得にもAndroidの `RECORD_AUDIO` 権限が必要です。既に許可している場合は、この画面は省略されます。
5. Androidの共有確認で **「今すぐ開始」** などを押します。画面共有のような表示でも、このアプリは映像用VirtualDisplayを作らず、音声だけを取得します。Android 13以降では先に通知の許可も求めます。通知を拒否すると通常の通知一覧から停止できない場合があるため、アプリ画面から停止します。
6. Braveでいつもの再生元を開き、有線で聴こえることを確認します。アプリへ戻るとメーターとRMS／ピークが動きます。読み取りサンプルが増えるだけでは、音の取得成功とは判定しません。
7. ブラウザで10秒ほど一時停止し、アプリへ戻ってメーターが無音へ変わることを確かめます。周囲で声や手拍子を出しても、停止中にメーターが反応しないことも確認できます。再開すると再び反応するか比べます。
8. 終了は **「取得を停止」**、または通知欄の **「停止」**。終了理由が表示され、「取得を開始」が再び使えれば終了処理が完了しています。
9. **「今回／直近のログを共有」** を押し、Android標準の共有先から保存先を選びます。共有は利用者が選んだ先への操作です。自動送信はしません。次の試験を始める前に必要なログを保存してください。

画面が長い場合は上下にスクロールしてください。RMS／ピークはdBFSで、0に近いほど大きく、デジタルゼロは−120表示です。ブロックRMSが−60 dBFS未満なら「無音」に集計するため、小さな音や音源中の間も含みます。

取得中のメモ欄を書き換え、**「現在のメモをログに記録」** を押すと、再生／一時停止や試験段階などの目印を残せます。ブラウザ前面かどうかはアプリが自動判定しません。画面オン／オフとProbe自身の表示／非表示は自動記録します。

## Chrome・Braveと画面オフを比べる

同じ再生元・音量・有線イヤホン・電池設定で比較します。ブラウザごとに取得を一度止め、新しいセッションを始めます。再生元の名称やプレイヤーをメモしてください。再生元の許可・保護・ブラウザの実装によって取得できないことがあります。

| 試験 | 操作 | 成立の目安 |
| --- | --- | --- |
| ブラウザ背景 | 再生したままProbeへ戻る。10秒一時停止と再開も比べる | 音量変化と停止中の無音が対応する |
| ブラウザ前面 | Probeを開始後、ブラウザを前面にして30秒以上再生する | 後からログの対象時刻の音量とサンプル増加を確認できる |
| 画面オフ | 再生したまま電源ボタンで消灯。まず約10分、耳でも再生継続を確認する | `screen_on:false` の区間にも音量とサンプル増加が続き、読み取りの大きな途切れがない |

画面オフ試験後はスマホを解除し、Probeへ戻って停止・共有します。10分は初回の暫定目安で、実利用時間の保証ではありません。まず標準設定で試し、失敗したときだけ **Wake Lockあり**、必要なら **アプリ単位の電池最適化設定の変更**を別セッションで比較します。設定を変えた内容はメモへ残してください。Wake LockやフォアグラウンドサービスだけでDoze・ColorOSを常に回避できるとは扱いません。

USB接続中は充電されます。非充電での継続性は、別にケーブルを外して試験し、共有したログで確認します。adbで状態を確認した試験を、USB非接続・完全な省電力条件の結果と混同しません。

## 許可・停止を確認する

- 録音を拒否した場合：取得は始まりません。「取得を開始」で再試行します。許可画面が出なくなった場合は **「アプリの権限・電池設定を開く」→ 権限 → マイク（録音）** で許可します。項目名はColorOSの表示に従ってください。
- 共有を拒否した場合：`projection_permission_denied` と終了し、再開始できます。取得開始のたびに標準の共有許可を求めます。
- 許可取り消し：取得中にAndroidの共有／キャストの通知・表示から停止できる場合は、その操作で停止し、Probeが終了状態になるか確認します。OSに該当する停止UIがなければ、その項目を未検証として記録します。新たに共有許可を与えるまでは再取得しません。
- 取得通知から停止：通知欄を開きRosebud Probeの「停止」を押し、Probeで `notification_stop` と終了するか確認します。
- 停止後の再開始：毎回新たに共有許可を与え、メーターが再び反応するか確認します。アプリの強制停止・OSによる終了は、次回起動時に `previous_process_exit_unknown` と表示する場合があります。正確な停止時刻や原因を断定せず、最後の約5秒ごとの保存集計を使います。

読み取りはあるのに音がゼロの場合、再生アプリ・再生元のキャプチャ許可、同じユーザープロファイルか、再生が続いているかを比べます。マイクへ切り替えて成功扱いにはしません。現在版での失敗だけでChrome／Brave全体が非対応とも断定しません。更新を試す場合は前後の版とログを保存します。

## このMacで再ビルドする

環境の作り直しは不要です。ターミナルで順に実行します。

```bash
cd '/Users/hyuta/Desktop/hyuta/遊び/bluetooth/rosebud-android'
source ./scripts/android-env.sh
./gradlew assembleDebug lint testDebugUnitTest
```

`source` はそのターミナルだけのJDK・SDK設定を読み込みます。新しいターミナルでは再実行してください。compileSdk／targetSdkは36、minSdkは31（Android 12）を維持しています。CPH2199のOSをAndroid 16へ更新する必要はありません。

- APK：`/Users/hyuta/Desktop/hyuta/遊び/bluetooth/rosebud-android/app/build/outputs/apk/debug/app-debug.apk`
- APK版：0.2.0／versionCode 2、デバッグ署名付き。
- Lint：`app/build/reports/lint-results-debug.html`
- 単体テスト：`app/build/reports/tests/testDebugUnitTest/index.html`

初回の依存取得にはネット接続が必要です。AGP 8.13.2、Kotlin 2.3.10、Gradle 8.13、JDK 21、既存のデバッグ鍵を維持しています。Android Studioで開く手順や環境で困った場合は [環境記録](docs/environment.md) を参照してください。

## USBで上書き導入・起動する

データ転送できるUSBケーブルで接続します。既に有効にしたUSBデバッグを維持していれば、設定を繰り返す必要はありません。上のビルドと同じターミナルで実行します。

```bash
adb devices -l
adb -d install -r app/build/outputs/apk/debug/app-debug.apk
adb -d shell am start -W -a android.intent.action.MAIN -c android.intent.category.LAUNCHER -n jp.hyoutan.rosebud/.MainActivity
```

一覧が `device` なら接続済み、`unauthorized` ならスマホを解除してUSBデバッグの確認を許可します。`-d` はUSB実機1台を指定します。複数台の場合は `-s <対象端末の番号>` を使います。

`Success` は導入成功、`Status: ok` は起動要求成功です。ロック中などに画面が出なければ、スマホを解除してアプリ一覧からRosebud Probeを開いてください。許可画面はアプリ内の「取得を開始」から出します。更新時もアンインストールは不要です。署名不一致のエラーでは自動的にアンインストールせず、元のデバッグ鍵を確認します。

## ログの保存量と診断

端末内に直近4セッションを保持し、各セッションのイベントを最大約1 MiB×3ファイルで巡回保存します。画面更新は約200〜250 ms、集計保存は約5秒です。最初のメタデータと直近集計は別に保持し、長時間試験の古いイベントは消えます。共有するのは**今回／直近の1セッション**で、共有用コピーも直近3個に制限します。必要な試験の直後に共有してください。

ログにはアプリ・OS・ブラウザの版、条件メモ、電源状態、利用可能な出力機器種別、画面状態、サンプル数、音量、無音区間、読み取り間隔・エラー、開始・停止理由を含みます。出力機器の一覧は利用可能な経路であり、実際に耳で聴いた経路の確認と併用します。端末のシリアル番号、閲覧URL、波形は自動収集しません。条件メモへ入力した内容は共有ログに含まれます。

USB接続中に共有操作が難しいときは、開発者がこのアプリの診断だけを読み出せます。

```bash
adb -d shell run-as jp.hyoutan.rosebud cat shared_prefs/probe.xml
adb -d shell run-as jp.hyoutan.rosebud ls files/probe-logs
```

必要なセッションのフォルダ名を指定し、パソコンへ保存する例です（`PROBE_SESSION` の値を上の一覧のフォルダ名に置き換えます）。

```bash
PROBE_SESSION='一覧で確認したセッションのフォルダ名'
adb -d exec-out run-as jp.hyoutan.rosebud cat "files/probe-logs/$PROBE_SESSION/header.json" > probe-header.json
adb -d exec-out run-as jp.hyoutan.rosebud cat "files/probe-logs/$PROBE_SESSION/events.jsonl" > probe-events.jsonl
```

長時間試験で巡回した場合は `events.2.jsonl`、`events.1.jsonl`、`events.jsonl` の順に併せて読みます。アプリの通常操作はこの開発者用コマンドなしで完結します。
