# Handyの位置・速度・時計の調整

2026-10-21、0.14.1/code19。本人が0.14.0のAndroid実動作を確認。その上で「フィニッシュを速く」「上だけ・下だけ・全体・小刻み」「速度と場所の緩急を組み合わせる」「基本は動き、たまに止まる」「3段階へ移動するボタン」「秒表示が飛ぶのを直す」と依頼。

## 変更点

旧版は最低速度で早く到着した後も予定秒数まで待ち、時計も区間完了時だけ更新していた。シナリオでは現在位置からの実距離と指定速度で移動時間を計算し、Firmware応答・到達位置・速度0を確認したら次へ進む。到着後の予定秒数待ちは撤廃。切替に必要な通信と確認の短い間までゼロになる保証ではない。本人が秒数を入力する有限テストは従来の予定時間待ちを維持する。

13候補を次の内容へ刷新。重みの保存キー・8/7/5分反復・20秒以上保持・80秒目安・音で選ぶ仕組み・別時計/乱数を維持する。

| 段階 | 位置の使い方 | 指定速度の基調 |
| --- | --- | --- |
| はじめ3候補 | 全体をゆっくり、上側をゆっくり、下側をゆっくり | 32〜60mm/s |
| 中間7候補 | 上側の加速、全体の緩急、下側の弱強、小刻み、上下の行き来、二連の小刻み、全体と小刻みの交代 | 60〜150mm/s、7分の中で基調を少しずつ上げる |
| フィニッシュ3候補 | 全体を速く、上下を速く、小刻みの位置を移しながら速く | 160〜260mm/s |

これは実測速度の保証ではなく今回の調整値。実際の送信は取得した機器の最低/最高速度内へ制約する。段階移動・候補切替・弱化解除では速さを滑らかに移すため、表の速度に即座に跳ねない。

上側は設定範囲内の60〜95%、下側は5〜40%、全体は5〜95%を基準にする。小刻みは中心を上下に移しながら18〜20ポイント幅。速度波と位置波は別周期（速度は約29.5秒、位置は約69秒、位置のまとまりは約14秒）で、同じ場所でも遅速があり、同じ速さでも別の場所を動く。音の密度・規則性はこの組み合わせへ控えめに反映する。中間は長期の加速と短い谷を重ねる。

各区間の短い休止の抽選確率は導入最大6%、中間最大3.5%、フィニッシュ最大2.2%。これは時間割合の保証ではない。休止は約200〜650msで、一部候補は休止なし。弱化も最低速度付近の狭い連続移動とし、Handy時計だけを保留する。

上限の初期85mm・アプリからの編集・機器可動範囲との照合・両端1mm余白は維持。更新前の稼働ログで取得機器範囲による実効上限約67.696mmを確認しており、保存した85mmへ無理に広げる処理はない。

## 操作と時計

Handyの時計の下に「はじめ／中盤／フィニッシュ」を横並びで配置。弱化していない実行中に段階を選べる。切替は専用停止→現在位置確認→新段階へ移動。未実行から勝手に開始しない。現在段階を色で示す。

時計を200ms間隔で、BLEの応答待ち・移動待ちから独立して更新する。時計更新は動作生成・方向・乱数・区間数を進めない。弱化中は保留し、停止と段階切替の古いタイマーが動作を復活させない。旧「片道の基準秒数」はシナリオで使わなくなったため設定画面から隠す（保存キーは維持）。入力テストの秒数入力は残す。
