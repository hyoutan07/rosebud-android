# Handyの入力テスト・共有

2026-10-21。本人から「入力して動作を確かめ、良い動きを送って調整したい」と依頼。「往復範囲・片道時間・回数」と「目標位置・移動時間の列」の**両方**を希望。本体はまだ未到着、Firmware/接続モードは到着後に確認する。

## 今回の範囲

Handyタブから開く専用テスト画面を追加。音声取得と独立し、入力・図・有限時間の無送信プレビュー・条件と感想のコピー/共有を用意する。通常のセッションや吸引を編集しない。実機送信は、停止経路・FW適合・初期位置合わせを確立した後の残件。本体未到着の間にソフトウェアを仕上げ、実機未確認を明記したデータを共有できるようにする。

- かんたん往復：下限、上限、片道秒数、往復回数。図上の始点は下限とし、上限→下限で1往復。初期位置合わせの送信は行わない。
- 位置列：図上の開始位置、各行に「目標位置%, 秒数」、列の繰り返し回数。ループの継ぎ目も連続した指令の設計として検査する。
- 数値は空欄で始める。見本はhintとして表示し、合意済みの好み・推奨値にはしない。復元しても開始しない。
- 既存の試作制限に合わせ、位置10〜90%、設計全体の幅20ポイント以内、1区間2〜20秒、最大20区間・120秒、速度相当10ポイント/秒以下。これは今回のソフトウェア試作の上限で、機器の物理仕様・体感の推奨値ではない。
- 入力確認で全区間の図と区間数/合計秒数を表示。プレビュー開始は明示操作で、入力に沿う有限の時計だけを進める。図の位置を「実機の現在位置」「到達済み」と表示しない。音声取得やサーバー接続は不要。
- 停止・画面を閉じる・バックグラウンド移行でプレビューの更新を解除。過去の区間をキューに積まない。実行中に条件を書き換えない。
- 画面内にも「すべて停止」を残し、必要時は既存の全停止を呼ぶ。Handyの実機テスト開始は無効のまま、理由を表示する。
- 「感想」欄と「条件をコピー」「共有」。単位付きの位置列・時間・図の始点・入力方式・プレビュー確認状態・実機未確認を同じデータへ含める。クリップボード/Android共有画面を使い、外部へ自動送信しない。音声・接続先・機器アドレスを含めない。
- コピー/共有/閉じる時に編集した内容だけ専用キーへ保存。既存設定を上書きしない。共有画面へ移っても打ち直しを減らす。

画面の配置：[確認用画面案](handy-trial-mock.html)。既存の承認済み機器タブ/配色を踏襲する。実装・模擬時計とデータ検証・ビルド/APKを先に行い、実物が届くまで機器スキャンや動作は始めない。
