# Rosebud Probe 引き継ぎ

更新日：2026-10-19（JST）。対象：**0.2.0の実装・初期検証完了時点**（コミット `3582ab0`）。

次の担当者が、会話を読み返さずに作業を再開するための文書。実機の事実は [検証記録](verification.md) と保存された根拠に基づく。今回の文書作成では再試験していない。

## 現在地

**同じスマホで再生するBraveの内部音声を、自作アプリで取得できることまで確認できた。** 初期の技術検証はユーザー判断で完了している。アプリは端末へ導入済みで、開発環境もそのまま使える。

ここまで確認したのは音声の取得・音量変化・一定条件での継続。音声から動作を生成する処理、Macとの通信、機器との連携は次段階。全体が完成したと解釈しない。

このチャットで以前扱った0.1.0は起動画面だけだったが、別タスクで0.2.0へ更新されている。古い会話の「音声取得は未実装」を現在の状態として引き継がない。[環境記録](environment.md) の0.1.0に関する記述も、環境構築当時の履歴として読む。

## 実機で分かったことと条件

対象は **CPH2199／Android 12（API 31）／ビルドCPH2199_11_C.42**。ColorOS V12・RAM 6 GBはユーザー申告。ブラウザはBrave 1.97.56、Chrome 155.0.8059.84で、検証時に更新していない。

| 確認済み | 成立した範囲・条件 |
| --- | --- |
| Braveの再生音を取得 | 再生に合わせて音量が変化し、一時停止でデジタルゼロになった。有線での聴取もユーザーが確認 |
| ブラウザを表示した状態とProbeへ戻った状態 | 短時間の取得継続を確認。初回の試験はWake Lockあり |
| 画面オフ中の取得 | **Wake Lockなしで約8分20秒**。読み取りエラー0。USB充電中、省電力モード有効、電池最適化の除外なし、ログ上は `device_idle:false` |
| 停止・再開始 | 画面から停止し、新しい許可で再開始できた。試験終了後にサービス・MediaProjectionが残っていないことも担当タスクで確認 |

画面オフ試験の10分は暫定目安だった。ユーザーが「一旦完了でよい」と判断し、約8分20秒で終了した。**10分達成でも、失敗による中断でもない。** 実利用に必要な継続時間はまだ決まっていない。

再生元の具体的なページ・プレイヤーは記録されていない。同じブラウザの全サイトや保護された音源でも取得できる、とは判断できない。証拠の数値・時刻は [verification.md](verification.md)、元となる抜粋は [検証根拠JSON](validation/2026-10-19-evidence.json) を参照する。生音声は保存されていない。

## 次の判断に必要な未確認事項

- **USBを外した非充電条件と、実利用時間での継続。** 今回はUSB充電・adb観測の影響がある。長時間の省電力制御まで成立したとは扱わない。
- **Chromeとの比較。** 版は確認済みだが、音声取得は未検証。Braveの結果を転用しない。
- 通知からの停止、許可拒否・取り消し、ログ共有先での読み取り、強制終了からの復帰。実装があることと実機で通ったことを区別する。
- 実際の再生元と必要な連続利用時間。次の試験を行う際は条件として残す。

ユーザーは今回の初期検証を終了する判断をしている。残項目をすべて消すためだけに再試験を始めず、次の目的に必要な確認を選ぶ。

## 再開時に知っておくこと

- ユーザーはAndroidアプリ開発の初心者。実機操作は、まず一つの操作を具体的に伝え、できたことを確かめながら進める方法が合っていた。複数の専門用語・長い操作手順を一度に渡さない。
- スマホの開発者向けオプションとUSBデバッグは有効化済み。このMacからの接続も許可済み。再接続時は認識を確認し、設定のやり直しを前提にしない。
- インストールの追加確認画面は出ず、正常に導入できた。音声取得の許可はアプリの開始操作時に本人が行う。確認画面が出なかったことだけで導入失敗と判断しない。
- このMacは構築済み。ビルド・導入は [README](../README.md) を使う。Studio本体のJBR 25と、ビルド用JDK 21は意図して分けた。環境を作り直す必要はない。
- 更新は既存のデバッグ署名を維持して上書きする。署名不一致で安易にアンインストールしない。保存済みの診断結果が必要なら、先に取り出す。
- 検証結果を読む際、サンプルが増えることだけを取得成功としない。再生・停止と音量の対応、本人の聴取確認も根拠にする。他の再生アプリの音が混ざらない条件で比較する。
- 必要な診断ログは試験後に取り出す。端末内ログは保持上限があり、長期間残るとは限らない。開発側はadbの `run-as` で読み取れたが、利用者の共有先で受領する一連の操作は未検証。
