# セッション画面の整理案

2026-10-21。状態：**機器タブ案を本人承認、吸引は常時展開・サイズ維持で採用**。実装・検証の正本は[0.12.0の結果](session-ui-implementation.md)。

## 本人の依頼と目的

今回の主目的は引き続きThe Handyの実装。操作が積み重なって画面が分かりにくくなったため、UI改善も同じ仕事に含める。本人から「セッション内でROSEBUDとThe Handyを切り替えたい」「見ていない動きタブを消して簡潔にしたい」「画面案を見ながら変えたい」と依頼を受領。

確定した方向と、以下の具体案の採用を区別する。画面を勝手に本実装せず、最初に操作できる案を提示する。既存生成・音声取得・吸引・保存設定の変更はこのUI整理に含めない。

## 提示した2案

| 案 | 構成 | 判断のための違い |
| --- | --- | --- |
| 機器タブ（推奨案） | セッション上部でROSEBUD / The Handyを切り替える | ワンタップで交互に操作でき、もう一方の状態もタブに残る |
| 機器一覧 | 最初に2機器の一覧を表示し、選んだ操作画面を開く | 最初の画面が簡潔。ただし別機器へ移るには一覧へ戻る |

両案の共通部分：

- 下の画面切り替えは「セッション」「接続・設定」の2つ。「動き」はなくす。固定/自動のパターン選択はROSEBUDの現在動作欄に残す。
- 上から音声・プレビューの状態、機器選択、選んだ機器の進行と操作。長い説明・波形見本・診断情報を通常操作の中央に並べない。
- ROSEBUD：進行時計・3段階・振動/Flickerの個別選択を1つのまとまりに。吸引はROSEBUD内の「独立操作」に残し、出力上限・休み・シナリオは折りたたむ。
- Handy：独立時計・現在のまとまり・生成範囲、弱化/解除・フィニッシュ移動。範囲と時間、出やすさの詳細は折りたたむ。
- 開始操作はどの機器に作用するか名前を明記。画面の切り替えだけでは、開始・停止・進行リセット・対象選択を行わない。
- 全停止は常に共通。下に両機器の状態を短く残す。Android本実装では、長く展開した場合も全停止を固定領域から押せる構成を維持する。
- 接続先・明示対象選択・実機/プレビュー・音声取得の準備は「接続・設定」。ログ/単発確認などはその中の詳細へ。
- 現在はHandy実出力が未成立であり、案でも「実機出力は準備中」「停止方式の確認待ち」としてプレビューを案内する。現時点の実動作成立と、将来の操作配置の案を混同しない。

## 本人の採用判断と、制御側の残件

- 本人は機器タブ案を承認。一覧案は採用しない。接続・設定の簡潔な配置も好評。
- 吸引は常時展開し、従来の文字・ボタン・スライダーを小さくしない。確認用の最初の案では折りたたみだったが、本実装は本人の訂正を優先する。
- 各機器の開始/終了、一時停止/再開と、共通全停止の最終的な責任分担。既存の一時停止は全対象停止である。案の機器別プレビュー終了を、そのまま実機の個別停止機能の実装合意にしない。
- 完成後のHandy実機用の開始前条件と初期位置合わせUI。これらは停止方式と実送信を仕上げるときに詰める。
