## 範囲と責任

- `BoilingFrog.kt`：Web（89397ee）の5つの依存波形と6ステージ。初回1140秒、以降780秒、第2ステージから周回。式・乱数の呼び出し順・予定したFlickerゼロを保持。
- `MotionController.kt`：Buttplug v3、機器定義の確認、対象機器の集合、生成、音量包絡、送信、応答、停止。単一のactorで直列化し、Activityは所有しない。通常出力の応答待ちは機器ごとに1件のみ。待機中の値をキューに追加せず、次回はその時点の最新の値を生成。
- `CaptureService.kt`：接続中はconnectedDevice FGS、音声許可後はmediaProjectionも追加。取得PCMのブロックRMSをcontrollerへ渡す。Brave前面でも同じサービスで生成・送信。接続だけ・取得開始だけで機器を動かさない。
- `MainActivity.kt`：保存可能な接続先、対象選択、明示的な動作開始、停止、取得許可、追従・上限。取得許可の結果はセッションID・phaseを照合し、終了後の遅い許可コールバックでは再開しない。
- `ProbeRepository.kt`：従来の音声診断を維持。取得前の接続診断は端末内 `control*.jsonl` 3世代、各約1 MiB。共有時に含める。音声ログと合わせて参照。生音声は保存・送信しない。

第2タスクで差し替える主な場所は `BoilingFrog.frame()` と `AudioEnvelope`。接続・停止・取得の責任を分けたまま利用できる。現版の波形の乱数は、Web同様、実際に生成したtickごとに進む。100 ms未満では生成しない。遅れたときに過去tickをまとめて再生しない。端末ごとに同じ実時間の乱数列を保証する設計ではない。

## 終了処理

「動作だけ停止」は生成のrun番号を無効化してStopDeviceCmdを送り、取得・接続を維持する。全対象の停止応答まで新しい開始を受け付けない。遅いScalar応答は出力を復活させない。

「全停止」、取得停止、通知停止、取得エラー・2秒以上サンプルなし・MediaProjection停止、通信／対象機器の消失は、生成を解除し、可能ならStopDeviceCmdを送って、取得と接続を終了する。停止応答は最大3秒待ち、未応答・切断を成功と書かない。機器ごとのStopDeviceCmd Errorを処理し、他の対象の応答を待つ。片方が成功でも全体を成功とせず、一部の停止未確認と表示する。プロセス終了後もSTART_NOT_STICKY。明示的に再接続・対象選択・開始が必要。

実機のMaxPingTimeは0だった。通信が完全に届かない状態で端末から機器の物理停止を保証したとは扱わない。実機での切断試験とサーバー側挙動は検証欄で記録する。

### 実装中の失敗と修正

- スマホ192.168.11.3／Mac192.168.40.78で3秒の接続timeout。生成・送信0件でエラーを表示し、サービス終了。同じWi-FiへそろえるとMacは192.168.11.10へ変化した。アプリで接続先を編集・保存。
- 日本語IMEで数字・句点・スラッシュが意図せず変換された。ASCII入力指定に加え、全角正規化・句点変換・IPだけの入力へ対応。キーボード設定は変更していない。
- 2台の停止Errorを待つ再現ケースを追加。最初の複数機器テスト実行は、停止応答を保留したテスト側の後処理で失敗。保留設定の解除と模擬時計を進める順を修正し、最終25件成功。製品コードの機器消失時の停止処理も別途修正した。
- 初期の探索用実行には0.3.0の更新でプロセスを入れ替えた区間があり、正常な画面停止の確認に使わない。その後は更新前に全停止応答・サービス終了を確認している。
