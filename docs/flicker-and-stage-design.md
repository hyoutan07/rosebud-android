# 実機の使用感を踏まえたFlickerと段階操作の見直し

更新：2026-10-20 JST。状態：**画面案を本人が承認。単発確認・段階スキップを0.5.0へ実装、物理値は未測定、間によるFlicker生成は未反映**。0.4.0の確認結果は [android-second-task.md](android-second-task.md)。[確認用画面案](flicker-and-stage-mock.html)は説明だけで、通信・機器操作を行わない。

## 本人から確認できた要望

- 振動は現状の感触を基準にする。Flickerとは弱さの表現を分ける。
- Flickerは、少し動くだけでは一動作にならず、ある程度の時間動かす必要がある。弱さは「動かす→少し止める→動かす」といった間で表したい。
- 一動作の秒数は実機で試さないと分からない。Flickerの動きは強めなので、慎重に設計し、本人と一緒に動かして確かめたい。
- 基本の進行を「はじめ→中間→フィニッシュ」として、途中から中間やフィニッシュへ進めるボタンがほしい。何もしなければ自動進行し、エンドレスへ至る。

これは単にFlickerの出力上限を上げる要望ではない。0.4.0では振動・Flickerをどちらも小さな連続値へ落としていた。Flickerは一動作を成立させる運転区間と、間隔の設計が必要。**成立する出力・最短時間・心地よい間隔は未測定**で、本人の発言から推定値を確定させない。

## 先に行う単発確認の画面案

1. 既存の機器一覧から対象を明示選択。初回は1台ずつ確認する案。接続・選択だけでは動かない。
2. Flickerだけを1回試す独立した操作にする。振動は0で、一動作を判断しやすくする案。第3系統は送らない。
3. 出力と継続時間を表示し、毎回本人が「この条件で1回試す」を押す。出力・時間の初回値は本人と確認してから設定する。
4. 自動反復・自動増量・終了後の自動再開はしない。操作は1回の運転→停止要求→停止応答の確認までを一組にする。
5. いつでも全停止を優先。最短動作時間の途中でも、本人の停止・取得／通信異常を理由に停止を遅らせない。停止未確認は次の試運転へ進めない。
6. 条件・本人の見た動作・送信／停止応答を記録し、出力か継続時間の片方だけを変えて比較する。最初は動き出す出力、次に一動作が成立する時間、その後に間を確認する。

この確認を通常シナリオの途中で自動挿入しない。0.4.0の上限35/34%を、単発確認での推奨出力・物理的に適切な値とはみなさない。保存済みの通常設定を勝手に書き換えない。サーバーへの停止要求が届かない状態の物理停止は未検証のまま扱う。

## 確認後のFlicker生成案

| 状態 | Flickerの表し方 |
| --- | --- |
| 極弱 | 成立する一動作 → 長めの間 → 次の一動作 |
| 弱め | 成立する一動作 → 短めの間 → 次の一動作 |
| 強め | 動かす区間を長く／間を少なくして連ねる |
| 静かな音 | 一動作を崩さず、次の動作までの間や頻度を弱める。時計は継続 |

- 「レシピ30〜60秒」「その中の一動作」「動作間の休止」を別の時間として管理する。
- 音の瞬間的な変化で進行中の一動作を細切れにしない。継続中の運転値の変更も、成立する範囲・上限内で扱う。
- 運転値を極小に落とし続けることを弱さの基本表現にしない。本人の出力上限を自動で超えない。
- 振動は今の生成を基準にし、Flickerの間へ連動して勝手に切らない。
- 新しい「Flickerの間」は演出として予定する休止。現仕様の「無音中は予定レスト以外のFlicker指令が常に正値」という条件は、この方式へ合わせて改訂が必要。時計継続と故障時の停止は維持。
- 既存レストA/Bの予定と一動作が衝突しないよう、開始前に時間を確保する。通常の予定休止と、全停止・異常停止を分ける。

## 段階スキップの画面案

セッションの時間帯表示の近くへ配置する。新しい15分シナリオだけを対象とし、比較用19分は当面維持する案。

```text
はじめ ───── 中間 ───── フィニッシュ → エンドレス
 現在        [中間へ]       [フィニッシュへ]
```

- はじめから中間へ、はじめ／中間からフィニッシュへ直接進める。自動進行は維持し、押す必要はない。
- 既存の0〜5分を「はじめ」、5〜15分（12〜15分の移行を含む）を「中間」、15分以降を「フィニッシュ・エンドレス」とする案。配分の具体値は別途維持／調整を判断。
- フィニッシュはアプリの終了ではなく、その後も緩急を混ぜてエンドレス継続する意味。
- 表示するセッション経過は実際の運転時間を保つ。段階へ進めた分は進行位置として別に扱い、実際に15分使ったと誤表示しない。
- 明示的なスキップは通常の30〜60秒保持の例外。ただしFlickerの進行中の一動作は成立させ、次の動作から新段階へ短く移行する案。通常の自動段階境界ではレシピ保持を維持。
- 一時停止中の段階指定は、再開まで機器を動かさない。停止待ち・通信異常では操作を無効化する。
- 戻す操作・任意の時間スライダーは今回の要望に含めず、まず前へ進める操作に絞る。

2. 単発確認と段階スキップを実装・機器なしで停止優先と遅いコールバックを検証し、APKを用意。[0.5.0の実装・確認状態](flicker-trial.md)。

4. 確認した値を基にFlickerの生成と段階スキップ時の一動作完走を実装。値をMotionDefaultsへ集約し、振動の現状と保存設定を維持。
