# Handy直接BLE実装

2026-10-21、本人がHandy直接BLE / Rosebud既存Intifaceの併用案を承認し、以前のシナリオを使った実装を依頼。初期の位置上限は8.5cm、アプリから変更可能とする。これは環境側の希望上限で、Handy本体の可動仕様と断定しない。

## 今回の実装範囲

- Handy専用の接続ボタン。Androidの付近のデバイス権限を使い、明示操作で検索・接続。接続だけで動かさず、自動再接続や自動再開なし。
- 直接BLEはHandyServiceが所有し、Rosebudは従来のCaptureService / Intifaceを維持。同じHandyへIntifaceとアプリを同時接続しない。
- 位置上限の初期値85mm。機器が返す可動下限からmin(保存上限, 機器可動上限)へ0〜100%を対応させる。位置の丸めに備え両端1mmを空ける。例として機器下限5mm・保存上限85mmなら0%は6mm、100%は84mm。設定範囲が2mm以下なら拒否。停止中に1〜12cmで編集・保存、開始時に読み込む。稼働中には変えない。
- シナリオは導入8分→中間7分→フィニッシュ5分のまとまりを変化させて反復。導入3・中間7・フィニッシュ3候補、音の特徴と重みで選ぶ。20秒以上保持し、音変化または80秒目安で動作の区切りに切替。
- Handyだけ弱めるとHandyの時計だけ保留し、解除時に戻す。手動フィニッシュ。既存Rosebudの時計や出力生成は変更しない。
- 入力テストの往復/位置列を実機送信へ接続。開始位置への移動を明記し、その到達確認後に有限列を実行。図は予定値で実測位置と混同しない。条件と感想をコピー/共有できる。
- 動作範囲・有限値・データ鮮度・停止中の速度を確認して開始。開始位置が設定範囲外なら勝手に移動せず拒否。Firmware応答と到達位置/速度を別に確認し、期限切れは停止要求・自動再開なし。
- 専用停止715を優先し、未送信動作・以前のタイマーを破棄。全停止はHandy/Rosebud/音声取得へ作用。通知からも停止可能。

## 実機診断から反映する制約

[Macでの実測](handy-ble-probe.md)：FW4.3.0+dcee7e58で専用停止・現在位置・速度・可動範囲の応答、100mm往復と途中停止を確認。Androidへ移す際は再検証が必要。

希望速度が本体の最低速度を下回ると、指定秒数より早く着く場合がある。各区間は移動後の待機を含む予定時間とし、「10秒かけて移動」とは表示しない。最大速度は読取設定で制約。機器設定の書込み、校正、モード切替はしない。

[Android権限](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions)と[背景通信](https://developer.android.com/develop/connectivity/bluetooth/ble/background)を参照し、connectedDeviceの通知付きサービスを採用する。プロセス終了・通信断時の物理停止は保証しない。確認できない場合は画面で区別する。

## 検証・導入

0.14.0/code18を実装・CPH2199へ上書き更新済み。167テスト成功、ビルド成功、Lintエラー0/警告12。既存control_settings.xmlは更新前・起動後ともバイト一致。Handy待機画面で初期設定上限8.5cmと直接接続ボタンを目視確認。Service・MediaProjectionなし。機器スキャン・接続・運動は自動で開始していない。

[検証記録](validation/2026-10-21-handy-direct-0.14.0.json)・[導入画面](validation/handy-direct/installed-handy.png)。APKは`app/build/releases/rosebud-0.14.0-debug.apk`、SHA-256 `8140cab9444d3b13ed9fa5b943d20930f9003a8002ae74cb0c5ed51aad41a24c`。

Android端末での接続/実移動/途中停止、画面オフと併用の確認は未実施。実機調査のMac結果だけでAndroidの成功とは扱わない。次は本人が「Handyに接続」で付近のデバイスを許可して接続し、短い実動作を別ケースとして確認する。接続だけでは移動命令を送らない。

### Androidからの初回接続（21:04 JST）

本人が接続成功と申告。handy_stateでconnected=true、preflight成立、受信位置12mm・設定上限85mmを読取確認。running=false、trial_active=falseで開始要求ログなし。保存設定follow=trueかつ音声未取得のため開始ボタンが無効だった。単体で試すなら接続・設定の「音に合わせる」をOFF、音連動なら先に音声取得が必要と案内。機器運動はこの確認では開始していない。

### 動作確認とシナリオ改善（0.14.1/code19）

本人がAndroidから「動いてる」と確認。0.14.0の実接続/実送信は成立。その上で、長い端点待ち・中心固定の往復・弱いfinish・秒表示の飛びを改善する依頼。現在は[位置と速度の緩急・段階ボタン・時計の修正](handy-scenario-retune.md)がシナリオの正本。入力テストの指定時間待ちとは区別する。
