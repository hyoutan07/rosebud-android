# Handy：本体の可動上限を使う

2026-10-22、0.14.8/code26。本人が実機の環境を調整し、最大の可動範囲まで使えるようになったため、シナリオも合わせる依頼。Handyなどの動作は停止済みと本人が明示。

## 動作と設定

- 従来の手動上限87mmによる制限から、本体が840応答で返すmaximumMmを使う「本体の上限まで使う」モードへ移行。今回の依頼に合わせ、初回起動でこのモードをONにする。既存の87mmなどの手入力値は残し、チェックを外せば再利用/編集できる。
- メーカー公称値や固定120mmを前提にしない。最大モードでは715停止の受理後に841 RequestSliderStrokeSetへmin=0/max=1を送り、本体側のストローク範囲を0〜100%へ戻す。841応答と840再取得の両方で0/1を確認してから絶対mmの下限/上限を採用する。接続時と開始準備時に行い、運転中には範囲を変えない。校正843・モーター設定2004・移動743はこの範囲設定では送らない。
- 最初に取得した88.100891mmは、その時点の本体側ストローク設定の上限であり、機構最大と確定しない。本人も「もっと上まで動くはず」「多分12cmまではいけるはず」と回答。最大モードは単にこの値を読むだけでなく、本体側の0〜100%設定と再読取りまで含める。
- 0〜100%を本体の下限+1mm〜上限-1mmへ換算する。従来の両端1mm余白を維持。例えば本体が5〜119mmを返せば目標は6〜118mmだが、この例を今回の実測値として扱わない。
- 波形は実際の可動幅から距離/周期を計算する。範囲拡大分は移動時間に反映し、同じ時間へ無理に詰めて加速しない。従来の序盤32mm/秒、中間の広い往復40mm/秒、終盤300〜400mm/秒の包絡と機器の上限は維持。
- 局所の位置/幅の揺らぎ、はじめ→中盤へ全幅を増やす比率、終盤の全幅多め/予定休憩なし、中間のメリハリ、音連動/乱数を維持する。[体験仕様](handy-pacing.md)。
- 接続/開始確認/段階切替の修正と独立Handyログも維持する。[復旧基盤](handy-rearm-recovery.md)。Handy状態ログには本体の下限/上限と最大モードのON/OFFも残す。

本人用の確定した上限変更であり、速度上限の引上げや予告なしの実動作は行わない。既存担当の利用上限を受けメインが継続した。

## 検証と導入

最大モードで旧87mmを越えて本体の上限を採用、手入力時は従来どおりmin(本体,指定値)、下限/上限の余白、広い距離で速度を増やさず時間を伸ばすことを回帰検証。実機の読み取りと更新状態は[検証記録](validation/2026-10-22-handy-maximum-0.14.8.json)。新しい全幅での移動は本人の開始後に確認し、自動開始しない。
