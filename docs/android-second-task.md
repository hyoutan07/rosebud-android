# 第2：音から自動選択するセッション

更新：2026-10-20 JST。**実装・自動検証済み、本人との2台動作試験は未実施**。親の `docs/android-second-task.md` が範囲の正本。親docsの状態更新はメイン担当。

## 実装

- `ScenarioEngine.kt`：8レシピを共通の形・状態・時間帯の重みから生成。30〜60秒ごとの境界で音特徴とスタイルに応じて重み付き抽選。同じレシピの重み0.2、3連続を除外。音や段階の変化で保持期限をリセットしない。
- レシピ内では音量包絡、立ち上がり、密度で強さ・周期・位相を変化。形は波／触れて離れる／疎なパルス／二連／上昇と戻り／保持と抜き／途中でほどける波／不規則なまとまり。カードは見本専用で生成器を変更しない。
- 軽量特徴は各PCM読み取りのRMSから作る。PCMは保持せず、数秒の立ち上がり時刻だけ保持。無音への弱化は判定の維持時間を待たない。音声の意味・種類を認識するものではない。
- レストA（振動だけ極弱）／B（両方ゼロ）／極弱／弱め／強めをログと状態で区別。無音からレストを新設しない。予定レスト以外は正値の下限を確保し、機器別量子化後も1段以上を送る。実際の物理的な最小値は未測定。
- 0〜5分導入、5〜12分中盤、12〜15分強めへ、15分以降エンドレス。段階境界でも現在のレシピは完走。45分以降も配分を維持し、上限を上げ続けない。旧 `BoilingFrog.kt` とWeb比較fixtureを保持。
- Native View/XMLの3画面。セッションに時刻・状態・生成波形・上限・音追従、動きに8つのカードと波形見本、接続・設定に機器選択・音声準備・プレビューと実機・既存診断を配置。開始／一時停止／再開と全停止は下部固定。
- プレビューはサービス側でScalarCmd・StopDeviceCmdを送らない。音追従OFFなら接続・取得なしでも生成可能。音追従ONでは実音声の取得が必要。初期はプレビューで起動し、実機へは明示変更と開始が必要。
- 一時停止は全対象のStopDeviceCmd応答を待ち、時計・seed・期限・レシピ位置を保持。再開は明示操作と0.7秒の立ち上がり。全停止は取得・接続も終了。停止待ち中に開始／再開不可、遅いScalar応答で復活しない。取得・通信異常は実行解除し、自動再開しない。
- 第1のサービス所有・機器別の最新値送信・2系統の量子化・全対象停止を再利用。同じ生成フレームを選択済み対象にだけ送り、追加検出機器を自動で加えない。アプリID・署名・保存設定を維持。
- 取得終了済みセッションへの`stop_requested`混入を修正。接続側の終了はcontrolログに残し、音声側は所有中のbusyセッションにだけ記録。

強めの予定時間と音で弱化した実際の指令値は別。音が小さいと強め状態中でも出力が小さくなる。レストAの振動は段階振幅×0.025。各状態へ短い反復の形を当て、無音でもレスト以外の動作指令はゼロにしない。物理的な強度・移動量の単位ではない。
