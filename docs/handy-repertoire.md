# Handy：終端余白の変更と広い範囲のレパートリー

2026-10-22、0.14.9/code27。本人が本体の終端余白5mmを0mmへ変更するよう明示し、停止済みと申告。さらに、広がった範囲で下側/上側を細かく動く、下から中間まで動くなど、場所ごとの動作を再考・実装する依頼。

## 実機での結果

0.14.9/code27をCPH2199に導入。218テスト・ビルド・Lint成功。電源中断の可能性を受け再接続し、余白は5mmのままと確認。停止/速度0を読んで固定設定を一度再試行したところ、Firmware 4.3.0はエラー100028、message「Overclock is not enabled」、data「x end buffer can only be set when overclock is enabled」を返した。変更成功ではなく、上限拡張は未適用（後続の本人回答で現在値の維持に合意）。オーバークロック、速度、校正、温度設定は変更していない。再接続後も余白5mm/通常上限118.993mmを読み直す。設定試行は移動を開始せず、運転中の読取り復旧経路への変更もない。

新しいレパートリーは現在の範囲でも使用できる。実機での体感は未確認。その後、本人が「なら別に今のままでも良い」と回答。通常上限118.993mm/余白5mmの維持で合意し、機構終端への追加拡張は行わない。

## 本体設定（試行の記録。本人合意で現在値を維持）

- 変更は利用者の今回の明示依頼に対する一度の操作。通常の接続ごとにモーター設定を上書きしない。接続・停止受理・速度0を読取り確認してから実行する。
- RPC2004 RequestSettingsSliderSetのfield3 xEndBuffer=0、field19 hasXEndBuffer=trueだけを送る。校正値xLimitStart/xLimitStop、速度、終端減速、温度、方向などのpresence flagは送らない。校正843も送らない。
- 2003の変更前/変更後を取得し、setting3が0、それ以外の全デコード値が同一であることを照合。違いがあれば成功と扱わない。841でストローク0〜100%を設定し直し、840/842で範囲/停止状態を再取得する。
- 終端余白を0にすると本体の下限も広がるが、今回の希望は上端の拡張なので、アプリでは以前の下限をminimum_mmとして残す。従来の下側位置を保ち、上側は本体が返す機構上限-1mmまで使う。例えば本体0〜123.993mm、保存下限5mmなら送信目標6〜122.993mm。
- アプリの両端1mm余白、開始前確認、速度制約、位置読取りの復旧、滑らかな段階切替は維持する。停止/切断後に設定操作や運転を復活させない。

公式配布スキーマの根拠は[0.14.8の資料](handy-maximum-range.md)と同じOnboarding bundle。RequestSettingsSliderSet.encodeのuint32キー24はfield3 uint、152はfield19 bool。公式settingsSetヘルパーは設定値に対応するhasフラグのみ付与する。今回のコマンドは固定2フィールドのみで、任意のモーター設定を指定する汎用機能は追加しない。

## 中盤の上側高速（0.14.10/code28）

本人の最終調整依頼：「上側高速を中間にシナリオとして30秒くらいたまに」。中盤へ入って45〜90秒後、半往復の切れ目から約30秒、上側68〜99%のランダム端点を往復する。高速区間は予定休憩を挟まず、通常速度の上限130mm/秒とは別に180〜220mm/秒の波を使う（本体上限400mm/秒以内）。半往復は最低160ms。上側への広い移動に該当するときは従来どおり40mm/秒で近づく。既存の滑らかな反転を使い、位置を飛ばさない。

終了後は通常のシナリオへ戻り、90〜150秒の間隔を空けて再び約30秒。発生時刻の抽選は独立したseed乱数。開始時刻/終了時刻は半往復の切れ目に合わせるので数百ms程度の差がある。画面とログは「上側を高速・30秒」。序盤・終盤では新規に出さず、段階変更時は既存の送信済み波だけ完了して通常の波へ移る。上限約11.9cm/終端余白5mm、通常レパートリー、音連動、段階の速度と休憩、接続/復旧処理は維持。

220テスト・ビルド・Lint成功、CPH2199へ更新済み。保存設定の一致と再接続後の速度0/停止待機を確認。結果は[検証記録](validation/2026-10-22-handy-upper-fast-0.14.10.json)に記録。新しい動作の体感は本人の開始後に確認する。

## シナリオの位置レパートリー

| 動き | 使う位置の基準 | まとまり |
| --- | --- | --- |
| 全幅往復 | 設定範囲の両端 | 2半往復の組 |
| 下側を細かく | 下側約2〜20%、往復幅6〜14% | 序盤/中盤は6〜12半往復を続ける |
| 上側を細かく | 上側約80〜99%、往復幅6〜14% | 序盤/中盤は6〜12半往復を続ける |
| 下から中間 | 下端2〜12% ↔ 中央40〜62% | 2〜4半往復 |
| 中間から上 | 中央38〜58% ↔ 上端88〜98% | 2〜4半往復 |
| 中央の波 | 中心35〜65%、幅20〜42% | 2〜4半往復 |

位置は実際の可動範囲へ毎回換算し、各半往復の端点と速さは少しずつ揺らす。細かな動作に入る際の位置移動と、その場所での小さな往復を分ける。幅75%以上の移動は序盤32/中盤40mm毎秒の上限を維持し、場所が切り替わる瞬間だけ急に速くしない。細かな波は中盤の上限85、終盤220mm毎秒を基準とし、序盤は本体最低速度付近32。各段階の通常速度包絡を越えない。細かな波は半往復を最低200msとし、1件ずつのBLE応答待ちで短い半往復が飛ばされることを抑える。

13候補の音特徴/重みの抽選は維持し、上寄り候補は上側の細かな波/中間→上、下寄り候補は下側/下→中間を選びやすくする。最低20秒の候補保持と、その中で数半往復ごとに場所を変えるレパートリーは別の時間軸。画面とログに実際の動作名も表示する。

全幅を選ぶ抽選率は導入8→18%、中盤25→50%、終盤96%を維持するが、抽選は動作のまとまりごと。細かな波は複数半往復なので、抽選率と半往復/時間比率は一致しない。終盤では局所のまとまりも2半往復にして全幅優勢を維持。音連動、seed乱数、反転の滑らかさ、導入の多めの休憩、中間のメリハリ、終盤の予定休憩なしを維持する。

## 確認範囲

固定2フィールドの設定ペイロード、他設定の変更を拒む読取り照合、下限を保った機構上限への換算、各位置レパートリーの端点、細かな波の連続したまとまりをテストする。実機では設定と停止中の範囲読取りまで行い、新しいシナリオは自動開始しない。[検証記録](validation/2026-10-22-handy-repertoire-0.14.9.json)。既存担当の利用上限を受け、確定した追加実装をメインが継続。
